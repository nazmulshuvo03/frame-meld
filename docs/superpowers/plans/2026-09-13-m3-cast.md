# M3 (Cast) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user sees what a generation will cost before they click it, spends real credits
on a real image, and gets every credit back when it fails.

**Architecture:** M3 adds the first thing in this system that costs money, so it adds the
first thing that can *refuse*: a quote/hold/settle ledger in front of the job queue. The
vehicle is the Cast stage — an LLM pass extracts characters from the story, and each
character gets one generated sheet image through a new `ImageProvider` adapter that
mirrors `LLMProvider` exactly. Images need somewhere to live, so `assets` and a `Storage`
protocol arrive here too (local disk in dev, S3/R2 later). The staleness engine grows two
new node types; nothing about its rules changes.

**Tech Stack:** Python 3.12 / FastAPI / SQLAlchemy 2.0 async / Alembic / arq + Redis /
httpx · Next.js 16.3.4 / React 19.2.8 / Tailwind v4 / Vitest · Postgres 16 · conda

**Spec:** [`docs/superpowers/specs/2026-09-09-framemeld-design.md`](../specs/2026-09-09-framemeld-design.md)
(§4.1 staleness, §4.3 credits, §5.1–5.3 data model, §6.3 providers, §9 milestones)

**Predecessors:** [`2026-09-09-m1-foundation.md`](2026-09-09-m1-foundation.md),
[`2026-09-10-m2-script.md`](2026-09-10-m2-script.md). Their execution ledgers are
[`m1-decisions.md`](../m1-decisions.md) and [`m2-decisions.md`](../m2-decisions.md).
**Read `m2-decisions.md` before Task 1** — three of its entries are load-bearing here:
the `@lru_cache`d-settings trap, the Gemini schema-dialect fix, and the recorded blocker
that M3 must give `GeminiLLMProvider` a real `cost_usd`.

## Global Constraints

Every task's requirements implicitly include this section. M2's constraints all still
apply; these are the ones this milestone will actually trip over.

**Toolchain**

- Python **3.12** via **conda**, env name `framemeld`. Never `uv`, never `venv`. Every
  backend command is prefixed `conda run --no-capture-output -n framemeld …`.
- Node **20+** (developed against v25.9.0). npm, not pnpm or yarn.
- Repo root is `F:\FrameMeld`. Backend package root is `services/backend`.
  `environment.yml` lives at the **repo root**.
- Postgres 16 and Redis 7 come from `docker-compose.yml` at the repo root.

**Database and models**

- Every enum column is built with `framemeld.models.columns.enum_column(enum_cls,
  constraint_name, length=20)`. All four of its internal arguments are load-bearing and
  each fails *silently* if omitted. Constraint names are schema-global — prefix them with
  the table (`character_state`, not `state`).
- Python enums are `enum.StrEnum`.
- **Every timestamp comes from `datetime.now(UTC)` in application code**, assigned
  explicitly. Postgres's `now()` is frozen for the whole transaction, so two rows written
  in one transaction would share a timestamp. Never add `onupdate=func.now()`.
- Migrations are generated with `alembic revision --autogenerate`, then **read and
  corrected by hand**. Autogenerate does not reliably emit `CheckConstraint`s declared in
  `__table_args__` — verify each one is present.
- UUID primary keys: `mapped_column(PgUUID(as_uuid=True), primary_key=True, default=uuid.uuid4)`.

**Hashing**

- `canonical_hash` (`framemeld/hashing.py`) accepts **only JSON-native values** and raises
  `TypeError` otherwise. Do not "fix" it with `default=str`. `uuid.UUID` must become
  `str(value)`; `Decimal` must become `str(value)`; `datetime` must not be hashed at all.
- **Downstream depends on upstream's `content_hash`, never its `input_hash`** (spec §4.1).

**Money**

- Credits are **integers**. 1 credit = $0.01 retail (spec §4.3). No floats anywhere in a
  balance, a quote, a hold, or a settle.
- The balance is **never a stored number**. It is `SUM(delta)` over the append-only
  `credit_ledger`, and it is only ever read inside a transaction that holds the user row
  lock (M3-D4).
- A user is **never charged more than the quote they were shown** (M3-D3).

**Authorization**

- Every read of a user-owned row goes through **one funnel**: `melds.service.get_meld`,
  the only place a `Meld` is selected by id, always filtering `user_id` and
  `deleted_at IS NULL`. Character, character-image and asset lookups resolve through it
  (or through `assets.user_id` directly) before returning anything.
- A row belonging to another user returns **404, not 403**.
- `HTTPException` instances are created fresh per raise by a `_not_found()`-style factory.
  A module-level instance accumulates tracebacks, each frame retaining that request's
  session and user.

**Tests**

- `pytest` with `asyncio_mode = "auto"`. No `@pytest.mark.asyncio` decorators.
- Fixtures available from `tests/conftest.py`: `db`, `client`, `logged_in`, `fake_redis`,
  `recording_queue`, and the autouse `_stub_llm_by_default`. **Task 8 adds an equivalent
  autouse guard for the image provider** — see its brief.
- Call `db.expire_all()` before asserting something was *persisted*. It is **synchronous**
  even on `AsyncSession`; `await`ing it raises `TypeError`.
- **Tests never reach the network.** The default LLM and image providers in tests are the
  stubs, and `conftest.py` forces them regardless of `.env`.
- Backend gates, all three clean: `pytest`, `ruff check src tests`,
  `ruff format --check src tests`.
- Frontend gates, all four clean: `npm test`, `npx tsc --noEmit`, `npm run lint`,
  `npm run build`.

**Style**

- `ruff` line length 100; selected rules `E4, E7, E9, E501, F, I, UP, B, DTZ, RUF`.
- Comments explain **why**, not what. M2's codebase sets the density — match it.
- No `# type: ignore`, no `Any` where a real type exists.
- Frontend: a data-fetching effect uses a `.then()/.catch()` chain, **not** `async/await`
  called from the effect body — `eslint-plugin-react-hooks` 7.x flags the latter under
  `react-hooks/set-state-in-effect` (see m2-decisions.md, Task 13).

**Product values fixed by the spec**

- 1 credit = $0.01 retail; a full film is roughly 2,500–3,000 credits (spec §4.3, §7).
- `characters.appearance` is *the* canonical, hashable visual description — it is what the
  image prompt is built from, and what a downstream `shot_image` will key on in M4.
- Job kinds used in M3: `generate_characters`, `generate_character_image`. Both already
  exist in `JobKind` — no enum migration is needed.
- `jobs.idempotency_key` is unique and equals `hash(kind, target_id, input_hash)`.
- Retry policy: 3 attempts, transport/5xx only. Provider content refusals are terminal
  with a **full** refund (spec §5.4, §4.3).
- **No Stripe in M3** (spec §10). Credits are granted, not bought.

## Decisions taken up front

Settled. Do not relitigate mid-task; if one turns out to be wrong, escalate rather than
quietly choosing differently.

**M3-D1 — `assets` and object storage arrive in M3, not M4.** The spec's milestone list
(§9) puts the assets table in M4, but M3 generates character sheet images and they have to
be stored somewhere; there is no coherent M3 without it. Storage lands now behind a
`Storage` protocol with a local-disk implementation. The S3/R2 implementation is deferred
until something *outside* the API needs to read a file — that is M5, where the Remotion
render service takes signed URLs it can fetch on its own.

**M3-D2 — `shot_characters` is deferred to M4.** Nothing in M3 reads it: shot images are
M4's job. Populating it needs an LLM pass that maps characters onto the existing shot
list, which is work M4's shot-image generation has to do anyway. Creating the table now
buys a migration and no reader. M4 creates and populates it together.

**M3-D3 — A quote is a ceiling, not an estimate.** Spec §4.3's rule is "Never surprise the
user." So settle **refunds** the difference when real usage came in under the quote, and
**never charges more** when it came in over — the overage is absorbed and logged at
`WARNING`. This removes an entire class of bug where a balance goes further negative than
the number the user agreed to, and it makes the quote a promise rather than a guess. Cost
if wrong: on a provider price rise we eat the difference until someone reads the log and
bumps the pricing table, which is the failure direction we want.

**M3-D4 — The balance is read under a `FOR UPDATE` lock on the user's row.** `SUM(delta)`
over an append-only table plus a later `INSERT` is a time-of-check/time-of-use race: two
Generate clicks 5 ms apart both see enough balance, both insert a hold, and the balance
goes negative by one action. `SELECT id FROM users WHERE id = :id FOR UPDATE` at the top
of the hold path serialises every balance-changing operation for that one user without
touching anyone else's throughput.

**M3-D5 — Settlement is computed in retail credits, not from the provider's bill.** The
quote is a fixed retail price per action; settle compares *work actually done* against
*work quoted* (both in credits), not dollars against dollars. Reading spec §4.3's "the
difference between the held estimate and the adapter's real reported cost" literally would
mean charging users cost price and deleting the margin §7 depends on. Provider dollars are
still recorded (M3-D6) — they are margin data, not the billing input.

**M3-D6 — Adapters report a real `cost_usd`, and it is persisted on the job row.** Spec
§3.3 requires adapters to report truthfully. M2 shipped `GeminiLLMProvider` with a
hardcoded `Decimal("0")` and recorded the debt; this milestone pays it. A new
`jobs.cost_usd` column is an extension to spec §5.4, justified because a job *is* one
provider call and `credits_held` already lives there — it makes margin measurable without
a second table.

**M3-D7 — Character extraction reads the story, not the script.** Spec §4.1's dependency
graph is `story ──> character`. Feeding the shot list in as well would make every
character stale whenever any shot was edited, which is both wrong and expensive.

**M3-D8 — One image per character in M3, `kind="sheet"`, `is_canonical=True`.** The other
`kind` values (`portrait`, `full_body`, `expression`) exist in the enum because the spec
lists them, but nothing produces them yet and nothing should until a screen needs them.

**M3-D9 — Signup grants 500 credits, and there is a `grant_credits` script.** No Stripe
until post-M6 (spec §10). 500 credits = $5 retail ≈ 40 character sheets, enough to exercise
the whole milestone without topping up, and small enough that running out is reachable in
testing — which matters, because "runs out mid-flow" is a path that must work.

**M3-D10 — `IMAGE_PROVIDER` defaults to `stub`,** exactly like `LLM_PROVIDER`, so the app
and the suite both run with no key and no network. `conftest.py` forces the stub
regardless of `.env` (the M2 trap, see m2-decisions.md).

**M3-D11 — Task 8 opens with a throwaway live probe, not with adapter code.** M2's lesson,
paid for once already: the published Gemini docs and the deployed API disagreed about
`responseSchema`, and nothing but a real call surfaced it. The image API's request and
response shape gets confirmed against the real endpoint *before* an adapter is written
around an assumption.

**M3-D12 — `ImageProvider.generate` takes reference images as `bytes`, not URLs.** Spec
§3.3 sketches `refs: list[str]`, which presupposes that every asset has a URL the provider
can fetch. Nothing serves a publicly reachable URL in M3 — storage is local disk behind an
authenticated route — and an image model needs the pixels either way. Bytes work for both
the local and the eventual S3 backend, and for both the inline-data and file-upload
request shapes. M3 passes an empty list (a character sheet is a root artifact with no
references); M4 is the first caller that passes anything.

```python
import uuid
from decimal import Decimal

import pytest
from sqlalchemy import delete, select, text
from sqlalchemy.exc import DBAPIError, IntegrityError

from framemeld.models.asset import Asset
from framemeld.models.cast import Character, CharacterImage, CharacterImageKind, CharacterRole

from framemeld.models.meld import Meld

async def _user(db) -> User:
    user = User(email=f"{uuid.uuid4()}@example.com", password_hash="x")
    db.add(user)
    await db.flush()
    return user


async def _meld(db, user: User) -> Meld:
    meld = Meld(user_id=user.id, title="T")

async def test_deleting_a_meld_cascades_to_characters_and_their_images(db):
    """Melds are soft-deleted in the app, so this never fires in practice --
    but the FKs must still be right, or a future hard delete or a data
    migration leaves orphans."""
    user = await _user(db)
    meld = await _meld(db, user)
    character = await _character(db, meld)
    asset = await _asset(db, user)
    db.add(
        CharacterImage(
            character_id=character.id,
            kind=CharacterImageKind.SHEET,
            content_hash="d" * 64,
            input_hash="e" * 64,
            state=ArtifactState.FRESH,
            asset_id=asset.id,

    assert (await db.execute(select(Asset))).scalars().all() != []
```

```python
import enum
import uuid
from datetime import datetime

from sqlalchemy import DateTime, ForeignKey, Index, Integer, String, func
from sqlalchemy.dialects.postgresql import UUID as PgUUID
from sqlalchemy.orm import Mapped, mapped_column

from framemeld.db import Base
from framemeld.models.columns import enum_column


class CreditKind(enum.StrEnum):
    """Spec section 5.1. `hold` and `settle`/`refund` always come in pairs:
    a hold is taken before a provider is called, and exactly one settle or
    refund closes it once the job is terminal."""

    PURCHASE = "purchase"
    GRANT = "grant"
    HOLD = "hold"
    SETTLE = "settle"
    REFUND = "refund"


class CreditLedger(Base):
    """Append-only. The balance is SUM(delta) over these rows and is never
    stored anywhere (spec section 4.3) -- that is what makes it impossible
    to corrupt with a lost update.

    Nothing at the database level enforces append-only; a trigger would,
    and is deliberately not here. The rule is held in one place instead
    (credits/service.py, which only ever INSERTs) because a trigger is a
    second source of truth that migrations then have to maintain.
    """

    __tablename__ = "credit_ledger"
    __table_args__ = (Index("ix_credit_ledger_user_created", "user_id", "created_at"),)

    id: Mapped[uuid.UUID] = mapped_column(
        PgUUID(as_uuid=True), primary_key=True, default=uuid.uuid4
    )
    user_id: Mapped[uuid.UUID] = mapped_column(
        PgUUID(as_uuid=True), ForeignKey("users.id"), index=True
    )
    #: Negative is a spend. Integer credits only: 1 credit = $0.01 retail,
    #: and a float balance would eventually drift.
    delta: Mapped[int] = mapped_column(Integer)
    kind: Mapped[CreditKind] = mapped_column(enum_column(CreditKind, "credit_ledger_kind"))

    #: Both nullable: a grant belongs to no job and no Meld.
    job_id: Mapped[uuid.UUID | None] = mapped_column(
        PgUUID(as_uuid=True), ForeignKey("jobs.id", ondelete="SET NULL"), nullable=True, index=True
    )
    meld_id: Mapped[uuid.UUID | None] = mapped_column(
        PgUUID(as_uuid=True), ForeignKey("melds.id", ondelete="SET NULL"), nullable=True
    )
    description: Mapped[str] = mapped_column(String(200), default="")

    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
```

`ondelete="SET NULL"` on both foreign keys, deliberately: a ledger row must outlive
whatever it refers to. Deleting a job must never delete the record that a user was charged

```python
from framemeld.models.job import JobKind

#: Bump when any price below changes. Stored on nothing yet; M6's purchase
#: flow will want it on the ledger row so an old charge can be explained
#: against the table that produced it.
PRICING_VERSION = 1

#: Retail credits per action. 1 credit = $0.01 (spec section 4.3).
#:
#: A fixed price per action, not a function of the provider's bill: the
#: user is quoted before they click and the quote is a ceiling (M3-D3), so
#: the number here has to be knowable in advance. The markup over provider
#: cost is roughly 4x, which is what spec section 7's ~$6.90 cost and
#: ~$25-30 retail imply.
#:
#: generate_characters: one LLM call over a few thousand tokens, well under
#: a cent at Flash-Lite rates.
#: generate_character_image: ~$0.02 (Imagen 4 Fast) to ~$0.04 (Nano Banana)
#: per image -- see providers/rates.py, and re-check both before changing
#: this number.
QUOTES: dict[JobKind, int] = {
    JobKind.GENERATE_CHARACTERS: 5,
    JobKind.GENERATE_CHARACTER_IMAGE: 12,
}


def quote_for(kind: JobKind) -> int:
    """What this action costs, in credits.

    Raises KeyError for an unpriced kind rather than returning a default.
    A default of 0 would quote future work as free and only be noticed on
    a revenue report; a default of "something large" would refuse work for
    no reason. Neither is better than failing at the call site.
    """
    return QUOTES[kind]
```

```python
#: The kinds that close a hold. Exactly one of these may exist per job.
_CLOSING_KINDS = (CreditKind.SETTLE, CreditKind.REFUND)


class InsufficientCredits(Exception):
    """Raised before any provider is called (spec section 4.3), so a user
    who cannot pay never triggers a bill we then have to eat."""

    def __init__(self, *, required: int, available: int) -> None:
        super().__init__(f"Needs {required} credits, has {available}.")
        self.required = required
        self.available = available


async def balance(db: DbSession, user_id: uuid.UUID) -> int:
    """SUM(delta) over the append-only ledger (spec section 4.3).

    Never cached and never stored: a materialised balance is the one thing
    that can silently disagree with its own history.
    """
    total = await db.scalar(
        select(func.coalesce(func.sum(CreditLedger.delta), 0)).where(
            CreditLedger.user_id == user_id
        )
    )
    return int(total or 0)


async def _lock_user(db: DbSession, user_id: uuid.UUID) -> None:
    """Serialise every balance-changing path for one user (M3-D4).

    SUM-then-INSERT is a time-of-check/time-of-use race: two Generate
    clicks milliseconds apart both read a sufficient balance, both insert a
    hold, and the user ends up owing more than they had. Locking the user
    row makes the read and the write one critical section, per user, without
    touching anyone else's throughput.
    """
    await db.execute(select(User.id).where(User.id == user_id).with_for_update())


async def _add(
    db: DbSession,
    *,
    user_id: uuid.UUID,
    delta: int,
    kind: CreditKind,
    job_id: uuid.UUID | None = None,
    meld_id: uuid.UUID | None = None,
    description: str = "",
) -> CreditLedger:
    row = CreditLedger(
        user_id=user_id,
        delta=delta,
        kind=kind,
        job_id=job_id,
        meld_id=meld_id,
        description=description[:200],
    )
    db.add(row)
    await db.flush()
    return row


async def grant(
    db: DbSession, user_id: uuid.UUID, credits: int, description: str
) -> CreditLedger:
    """Credits given, not bought. Stripe is post-M6 (spec section 10), so
    this is the only way credits enter the system in M3."""
    return await _add(
        db, user_id=user_id, delta=credits, kind=CreditKind.GRANT, description=description
    )


async def hold(
    db: DbSession,
    *,
    user_id: uuid.UUID,
    job_id: uuid.UUID,
    meld_id: uuid.UUID | None,
    credits: int,
    description: str,
) -> CreditLedger:
    """Take the money before the work starts.

    Must run in the same transaction as the job row it refers to: a commit
    between the two would leave either a job nobody paid for or a charge
    for a job that does not exist.
    """
    await _lock_user(db, user_id)
    available = await balance(db, user_id)
    if available < credits:
        raise InsufficientCredits(required=credits, available=available)

    return await _add(
        db,
        user_id=user_id,
        delta=-credits,
        kind=CreditKind.HOLD,
        job_id=job_id,
        meld_id=meld_id,
        description=description,
    )


async def _already_closed(db: DbSession, job_id: uuid.UUID) -> bool:
    existing = await db.scalar(
        select(CreditLedger.id)
        .where(CreditLedger.job_id == job_id, CreditLedger.kind.in_(_CLOSING_KINDS))
        .limit(1)
    )
    return existing is not None


async def settle(
    db: DbSession,
    *,
    job_id: uuid.UUID,
    user_id: uuid.UUID,
    held: int,
    used: int,
    description: str,
) -> CreditLedger | None:
    """Close a hold once the work is done, returning any unused credits.

    Returns None when there is nothing to write -- either the job was
    already closed, or the work cost exactly what was quoted. A zero-delta
    row is noise in a ledger a human has to be able to read.

    Never charges more than was held (M3-D3). Going over budget is logged
    by the caller and absorbed; the quote the user agreed to is a promise.
    """
    await _lock_user(db, user_id)
    if await _already_closed(db, job_id):
        return None

    refundable = held - min(used, held)
    if refundable <= 0:
        return None

    return await _add(
        db,
        user_id=user_id,
        delta=refundable,
        kind=CreditKind.SETTLE,
        job_id=job_id,
        description=description,
    )


async def refund(
    db: DbSession, *, job_id: uuid.UUID, user_id: uuid.UUID, held: int, description: str
) -> CreditLedger | None:
    """Give all of it back. Spec section 4.3: a failed job refunds in full,
    including a provider content refusal, which is terminal.

    Returns None if this job's hold was already closed -- arq can deliver
    the same message twice, and the ledger is append-only, so a second
    refund would be free money with no undo.
    """
    await _lock_user(db, user_id)
    if await _already_closed(db, job_id):
        return None

    return await _add(
        db,
        user_id=user_id,
        delta=held,
        kind=CreditKind.REFUND,
        job_id=job_id,
        description=description,
    )
```

```python
import re
from typing import Protocol

#: <user uuid>/<asset uuid>.<ext>, and nothing else. Keys are built by this
#: codebase and never by a user, but they become filesystem paths, so the
#: shape is enforced rather than trusted. With this pattern a traversal
#: sequence is not merely rejected, it is unrepresentable.
_SAFE_KEY = re.compile(
    r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}"
    r"/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}"
    r"\.[a-z0-9]{2,5}$"
)


def safe_key(key: str) -> str:
    if not _SAFE_KEY.fullmatch(key):
        raise ValueError(f"Unsafe storage key: {key!r}")
    return key


class Storage(Protocol):
    async def put(self, *, key: str, data: bytes, mime: str) -> None: ...

    async def get(self, *, key: str) -> bytes: ...
```

```python
import asyncio
from pathlib import Path

from framemeld.storage.base import safe_key


class LocalDiskStorage:
    """Files under one directory. The development backend, and the reason
    M3 needs no cloud credentials to run end to end."""

    def __init__(self, root: Path) -> None:
        self._root = Path(root).resolve()

    def _path(self, key: str) -> Path:
        path = (self._root / safe_key(key)).resolve()
        # Belt and braces. safe_key already makes traversal unrepresentable;
        # this is the check that still holds if someone loosens that regex
        # later without thinking about what it was protecting.
        if not path.is_relative_to(self._root):
            raise ValueError("Storage key escapes the storage root")
        return path

    async def put(self, *, key: str, data: bytes, mime: str) -> None:
        # `mime` is unused here and deliberately still in the signature: S3
        # needs it as ContentType at write time, and a protocol that only
        # fits the local backend would have to change the day the second
        # one arrives.
        path = self._path(key)
        path.parent.mkdir(parents=True, exist_ok=True)
        # to_thread because this runs inside the arq worker's event loop. A
        # couple of megabytes to a slow disk would otherwise stall every
        # other job in the same process for the duration of the write.
        await asyncio.to_thread(path.write_bytes, data)

    async def get(self, *, key: str) -> bytes:
        return await asyncio.to_thread(self._path(key).read_bytes)
```

Create `services/backend/src/framemeld/assets/service.py`:

```python
import hashlib
import struct
import uuid
from datetime import UTC, datetime

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession as DbSession

from framemeld.models.asset import Asset
from framemeld.storage.registry import get_storage

_PNG_MAGIC = b"\x89PNG\r\n\x1a\n"


def png_dimensions(data: bytes) -> tuple[int, int] | None:
    """Width and height from a PNG's IHDR chunk, or None.

    Eight lines of struct instead of a Pillow dependency: the only thing
    this codebase needs from an image decoder is two integers from a header
    that is always in the same place. Anything that is not a PNG returns
    None and the columns stay null -- they are metadata for a future UI,
    not something a generation depends on, so an unreadable format must not
    fail the job that produced the bytes.
    """
    if len(data) < 24 or not data.startswith(_PNG_MAGIC) or data[12:16] != b"IHDR":
        return None
    width, height = struct.unpack(">II", data[16:24])
    return width, height


async def store_asset(
    db: DbSession, *, user_id: uuid.UUID, data: bytes, mime: str, ext: str
) -> Asset:
    """Write the bytes, then record them.

    That order, deliberately: if the row's transaction rolls back we leak a
    file nobody references, which is garbage to collect later. The other
    order leaks a row pointing at nothing, which is a 404 in a user's
    gallery and a much worse thing to debug.
    """
    asset_id = uuid.uuid4()
    key = f"{user_id}/{asset_id}.{ext}"
    await get_storage().put(key=key, data=data, mime=mime)

    dimensions = png_dimensions(data)
    asset = Asset(
        id=asset_id,
        user_id=user_id,
        storage_key=key,
        mime=mime,
        bytes=len(data),
        sha256=hashlib.sha256(data).hexdigest(),
        width=dimensions[0] if dimensions else None,
        height=dimensions[1] if dimensions else None,
        created_at=datetime.now(UTC),
    )
    db.add(asset)
    await db.flush()
    return asset


async def get_asset(db: DbSession, user_id: uuid.UUID, asset_id: uuid.UUID) -> Asset | None:
    """Authorised on assets.user_id directly rather than through get_meld:
    an asset outlives the generation that produced it, and the serving
    route has no Meld in hand."""
    return (
        await db.execute(
            select(Asset).where(Asset.id == asset_id, Asset.user_id == user_id)
        )
    ).scalar_one_or_none()
```

```python
    """A fresh instance per raise -- see melds/router.py for why."""
    return HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Not found")
```

```python
import hashlib
import struct
import zlib
from decimal import Decimal
from typing import Any

from framemeld.config import settings
from framemeld.providers.base import ProviderRefusedError, ProviderResult

#: Small enough to keep the suite fast, large enough that a human looking
#: at one in a browser can tell it is a placeholder and not a failure.
STUB_SIZE = 64


def _chunk(tag: bytes, payload: bytes) -> bytes:
    return (
        struct.pack(">I", len(payload))
        + tag
        + payload
        + struct.pack(">I", zlib.crc32(tag + payload) & 0xFFFFFFFF)
    )


def solid_png(width: int, height: int, rgb: tuple[int, int, int]) -> bytes:
    """A real, valid PNG of one solid colour, from zlib and struct.

    Real bytes rather than a fixture blob because everything downstream
    treats these as an image: the sha256 becomes a content_hash, the asset
    service reads dimensions out of the IHDR, and a browser renders the
    result. A stub returning b"not-an-image" would let all three ship
    broken and only fail against a live provider.

    Colour type 2 (truecolour), bit depth 8, and every scanline prefixed
    with filter byte 0 -- the simplest encoding the format allows.
    """
    scanline = b"\x00" + bytes(rgb) * width
    return (
        b"\x89PNG\r\n\x1a\n"
        + _chunk(b"IHDR", struct.pack(">IIBBBBB", width, height, 8, 2, 0, 0, 0))
        + _chunk(b"IDAT", zlib.compress(scanline * height))
        + _chunk(b"IEND", b"")
    )


class StubImageProvider:
    """A local image model that costs nothing and never leaves the process.

    The default provider (M3-D10), so the app and the whole suite run with
    no API key and no network. Its output is *derived from the prompt*
    rather than fixed: two characters must not produce byte-identical
    sheets, or a test asserting that each character got its own image would
    pass against a broken generation path.
    """

    name = "stub"

    def __init__(self) -> None:
        self.model = settings.image_model

    async def generate(
        self, *, prompt: str, refs: list[bytes], params: dict[str, Any]
    ) -> ProviderResult:
        if not prompt.strip():
            # A real model asked to draw nothing would refuse or
            # hallucinate. Refusing keeps the failure honest and gives the
            # refund path something to exercise.
            raise ProviderRefusedError("There is nothing to draw yet.")

        digest = hashlib.sha256(prompt.encode("utf-8")).digest()
        return ProviderResult(
            text=None,
            bytes_=solid_png(STUB_SIZE, STUB_SIZE, (digest[0], digest[1], digest[2])),
            cost_usd=Decimal("0"),
            provider=self.name,
            model=self.model,
            raw={"stub": True},
        )
```

Create `services/backend/src/framemeld/providers/rates.py`:

```python
import logging
from decimal import Decimal

logger = logging.getLogger(__name__)

#: USD per 1,000,000 tokens, as (input, output). Captured from
#: https://ai.google.dev/gemini-api/docs/pricing on 2026-09-13.
#:
#: Keyed by the model id as configured, including the "-latest" aliases,
#: because that is the string the adapter has in hand. An alias's price can
#: move under it when Google rotates what it points at -- which is the main
#: reason this table is checked against the page rather than trusted
#: forever.
_TEXT_RATES: dict[str, tuple[Decimal, Decimal]] = {
    "gemini-flash-lite-latest": (Decimal("0.10"), Decimal("0.40")),
    "gemini-flash-latest": (Decimal("0.75"), Decimal("3.75")),
}

#: USD per generated image.
_IMAGE_RATES: dict[str, Decimal] = {
    "imagen-4.0-fast-generate-001": Decimal("0.02"),
    "imagen-4.0-generate-001": Decimal("0.04"),
    "gemini-2.5-flash-image": Decimal("0.039"),
}

_MILLION = Decimal("1000000")


def usd_for_tokens(model: str, prompt_tokens: int, output_tokens: int) -> Decimal:
    """What a completion cost, from the token counts the provider reported.

    An unpriced model is logged and costed as zero rather than raising.
    This number is margin observability, never the billing input (M3-D5):
    credits are quoted at a fixed retail price and settled against work
    done. Raising here would turn "we have not written this model's price
    down yet" into "the user's generation fails", which is the wrong trade
    by a wide margin.
    """
    rates = _TEXT_RATES.get(model)
    if rates is None:
        logger.warning("no token rate for model %s; recording cost 0", model)
        return Decimal("0")

    prompt_rate, output_rate = rates
    return (prompt_rate * prompt_tokens + output_rate * output_tokens) / _MILLION


def usd_for_image(model: str, count: int = 1) -> Decimal:
    """What an image generation cost. Same fail-soft rule as above."""
    rate = _IMAGE_RATES.get(model)
    if rate is None:
        logger.warning("no image rate for model %s; recording cost 0", model)
        return Decimal("0")
    return rate * count
```

```python
import base64
from typing import Any

import httpx

from framemeld.config import settings
from framemeld.providers.base import (
    ProviderRefusedError,
    ProviderResponseError,
    ProviderResult,
    ProviderTransportError,
)
from framemeld.providers.rates import usd_for_image

#: Longer than the text timeout: image generation is slower, and the
#: connect timeout stays short because a host that will not answer the
#: handshake is not going to draw anything either.
_TIMEOUT = httpx.Timeout(180.0, connect=10.0)

_RETRYABLE_STATUSES = frozenset({408, 409, 425, 429})

_REFUSAL_FINISH_REASONS = frozenset({"SAFETY", "RECITATION", "BLOCKLIST", "PROHIBITED_CONTENT"})


class GeminiImageProvider:
    name = "gemini"

    def __init__(self, transport: httpx.BaseTransport | None = None) -> None:
        if not settings.gemini_api_key:
            raise ValueError("GEMINI_API_KEY is not set but IMAGE_PROVIDER=gemini")
        self.model = settings.image_model
        # Injected only by tests, via httpx.MockTransport -- the same seam
        # the two text adapters use, for the same reason.
        self._transport = transport

    def _request_payload(self, prompt: str, refs: list[bytes]) -> dict[str, Any]:
        parts: list[dict[str, Any]] = [{"text": prompt}]
        # M3 never passes refs; M4 does, with each character's canonical
        # sheet. Inline rather than uploaded: a sheet is well under the
        # inline size limit and an upload is a second request that can fail
        # on its own.
        parts.extend(
            {"inlineData": {"mimeType": "image/png", "data": base64.b64encode(ref).decode()}}
            for ref in refs
        )
        return {
            "contents": [{"role": "user", "parts": parts}],
            "generationConfig": {"responseModalities": ["IMAGE"]},
        }

    @staticmethod
    def _extract_image(body: dict[str, Any]) -> tuple[bytes, str]:
        candidates = body.get("candidates") or []
        if not candidates:
            block_reason = (body.get("promptFeedback") or {}).get("blockReason")
            if block_reason:
                raise ProviderRefusedError(
                    "The image model declined this description. "
                    "Try rewording the parts it might have flagged."
                )
            raise ProviderResponseError("The image model returned no image.")

        candidate = candidates[0]
        if candidate.get("finishReason") in _REFUSAL_FINISH_REASONS:
            raise ProviderRefusedError(
                "The image model declined this description. "
                "Try rewording the parts it might have flagged."
            )

        for part in (candidate.get("content") or {}).get("parts") or []:
            inline = part.get("inlineData")
            if inline and inline.get("data"):
                try:
                    return base64.b64decode(inline["data"]), inline.get("mimeType", "image/png")
                except (ValueError, TypeError) as exc:
                    raise ProviderResponseError(
                        "The image model returned something that is not an image."
                    ) from exc

        raise ProviderResponseError("The image model returned no image.")

    async def generate(
        self, *, prompt: str, refs: list[bytes], params: dict[str, Any]
    ) -> ProviderResult:
        url = f"{settings.gemini_base_url}/models/{self.model}:generateContent"
        try:
            async with httpx.AsyncClient(timeout=_TIMEOUT, transport=self._transport) as client:
                response = await client.post(
                    url,
                    json=self._request_payload(prompt, refs),
                    headers={"x-goog-api-key": settings.gemini_api_key},
                )
        except httpx.HTTPError as exc:
            # str(exc) on an httpx error never contains request headers, so
            # the key cannot leak through here.
            raise ProviderTransportError(
                f"Could not reach the image model: {type(exc).__name__}."
            ) from exc

        if response.status_code in _RETRYABLE_STATUSES or response.status_code >= 500:
            raise ProviderTransportError(
                f"The image service returned {response.status_code}. This is usually temporary."
            )
        if response.status_code >= 400:
            # Deliberately without the body: this message reaches the user
            # through jobs.error.
            raise ProviderResponseError(
                f"The image model rejected the request ({response.status_code})."
            )

        try:
            body = response.json()
        except ValueError as exc:
            raise ProviderResponseError("The image model returned an unreadable reply.") from exc

        data, mime = self._extract_image(body)
        return ProviderResult(
            text=None,
            bytes_=data,
            # Priced per image, not per token -- there is no usage block to
            # read, so the rate table is the only source (M3-D6).
            cost_usd=usd_for_image(self.model),
            provider=self.name,
            model=body.get("modelVersion") or self.model,
            raw={"mimeType": mime},
        )
```

`raw` deliberately does **not** carry the base64 payload: it is stored in job/debug

```python
from framemeld.config import settings
from framemeld.hashing import canonical_hash
from framemeld.models.cast import MAX_CHARACTERS, Character, CharacterImageKind

#: Bump when the extraction prompt or schema changes in a way that would
#: produce a different cast from the same story. Part of CHARACTERS_PARAMS,
#: so bumping it correctly marks every existing cast stale.
CHARACTERS_PROMPT_VERSION = 1

#: Bump when the sheet prompt template changes. Marks every existing sheet
#: stale -- which is true, and expensive, so bump it deliberately.
SHEET_PROMPT_VERSION = 1

CHARACTERS_PARAMS: dict[str, object] = {
    "prompt_version": CHARACTERS_PROMPT_VERSION,
    # Lower than the script generator's 0.7: a cast list is extraction, not
    # invention, and the failure mode to avoid is confident embellishment.
    "temperature": 0.4,
    "max_characters": MAX_CHARACTERS,
}

SHEET_PARAMS: dict[str, object] = {
    "prompt_version": SHEET_PROMPT_VERSION,
    "size": "1024x1024",
}


def content_hash_for_character(character: Character) -> str:
    """Every user-editable field that changes what the character *is*.

    `order_index` is deliberately excluded, unlike Scene and Shot. A shot's
    position is part of the film; a character's position in a list is
    presentation. Including it would mean dragging a character up the cast
    list invalidated their artwork and charged the user to regenerate an
    identical picture.

    Leaving a field out here is not a small bug: M4's shot images key on
    this value, so an omitted field is one whose edit never invalidates the
    artwork generated from it.
    """
    return canonical_hash(
        {
            "kind": "character",
            "name": character.name,
            "role": character.role.value,
            "description": character.description,
            "appearance": character.appearance,
            "voice_id": character.voice_id,
        }
    )


def content_hash_for_character_image(asset_sha256: str) -> str:
    """What the image *is*: a hash of the bytes that were produced.

    A generated row still needs a content_hash, because spec section 4.1 is
    explicit that downstream keys on content_hash and never on input_hash --
    and in M4 a shot image's input_hash includes the content_hash of every
    character sheet it referenced. Wrapped in a labelled payload rather
    than storing the raw sha256, so a hash from this table can never be
    mistaken for one from another.
    """
    return canonical_hash({"kind": "character_image", "asset_sha256": asset_sha256})


def characters_input_hash(story_content_hash: str) -> str:
    """What would produce this cast if it were extracted right now.

    Reads the *current* provider configuration, the same rule M2's
    script_input_hash follows (D2): staleness and job idempotency are then
    the same function, so a row the UI shows as stale can never turn out to
    be a silent cache hit when the user presses Regenerate.
    """
    return canonical_hash(
        {
            "kind": "characters",
            "story_content_hash": story_content_hash,
            "provider": settings.llm_provider,
            "model": settings.llm_model,
            "params": CHARACTERS_PARAMS,
        }
    )


def character_image_input_hash(character_content_hash: str, kind: CharacterImageKind) -> str:
    """What would produce this image right now.

    Keyed on the character's content_hash -- what they look like now -- not
    on their input_hash. That is the whole point of the two-hash split: a
    human rewriting `appearance` must invalidate the sheet, and editing
    never changes an input_hash.

    Reads the *image* provider settings, not the LLM's: changing
    LLM_MODEL must not invalidate artwork no language model produced.
    """
    return canonical_hash(
        {
            "kind": "character_image",
            "image_kind": kind.value,
            "character_content_hash": character_content_hash,
            "provider": settings.image_provider,
            "model": settings.image_model,
            "params": SHEET_PARAMS,
        }
    )
```

```python
def build_character_messages(story_text: str) -> tuple[str, str]:
    """The user message is the story text, unwrapped and unpadded -- the
    same contract build_messages() established in M2, including that the
    stub treats an empty/whitespace user message as nothing to work from
    and refuses rather than inventing a cast."""
    return _SYSTEM, story_text


def _truncated(value: object, limit: int) -> object:
    return value[:limit] if isinstance(value, str) and len(value) > limit else value


class DraftCharacter(BaseModel):
    name: str = Field(min_length=1)
    role: CharacterRole = CharacterRole.SUPPORTING
    description: str = ""
    appearance: str = ""

    @field_validator("name", mode="before")
    @classmethod
    def _truncate_name(cls, value: object) -> object:
        # min_length=1 stays terminal: a nameless character is a missing
        # character. Overlong is different -- truncating keeps them.
        return _truncated(value, 120)

    @field_validator("description", "appearance", mode="before")
    @classmethod
    def _truncate_text(cls, value: object) -> object:
        return _truncated(value, 4000)

    @field_validator("role", mode="before")
    @classmethod
    def _known_role(cls, value: object) -> CharacterRole:
        """An invented role costs this field's fidelity, not the cast."""
        try:
            return CharacterRole(value)
        except ValueError:
            return CharacterRole.SUPPORTING


class CastDraft(BaseModel):
    characters: list[DraftCharacter]


def parse_characters(text: str) -> CastDraft:
    """Turn a provider's response into a draft, or fail terminally.

    Every failure here is a ProviderResponseError, which is not retryable:
    a model that answered with prose once will answer with prose again, and
    each attempt costs. The user sees the message, so it says what happened
    rather than quoting the body at them.
    """
    try:
        payload = json.loads(text)
    except (TypeError, json.JSONDecodeError) as exc:
        raise ProviderResponseError(
            "The model did not return a cast list. Try generating again."
        ) from exc

    try:
        draft = CastDraft.model_validate(payload)
    except ValidationError as exc:
        raise ProviderResponseError(
            "The model returned a cast list in an unexpected shape. Try generating again."
        ) from exc

    draft.characters = [c for c in draft.characters if c.name.strip()][:MAX_CHARACTERS]
    if not draft.characters:
        raise ProviderResponseError("The model found no characters. Try generating again.")
    return draft


async def apply_characters(
    db: DbSession, meld: Meld, draft: CastDraft, input_hash: str
) -> int:
    """Replace the Meld's cast with this draft.

    Replace, not merge, exactly as apply_script does: a regenerated cast is
    a new cast, and matching new characters to old ones would guess at an
    intent the user has not expressed. Their edits are protected by
    staleness *never regenerating on its own*.

    The cascade takes character_images with the characters, so a regenerate
    discards artwork the user paid for. That is the same trade the script
    stage already makes and the UI must say so before the click -- see
    Task 15's confirmation copy.
    """
    await db.execute(
        delete(Character)
        .where(Character.meld_id == meld.id)
        .execution_options(synchronize_session=False)
    )
    await db.flush()

    now = datetime.now(UTC)
    for index, drafted in enumerate(draft.characters):
        character = Character(
            id=uuid.uuid4(),
            meld_id=meld.id,
            order_index=index,
            name=drafted.name,
            role=drafted.role,
            description=drafted.description,
            appearance=drafted.appearance,
            content_hash="",
            input_hash=input_hash,
            state=ArtifactState.FRESH,
            created_at=now,
            updated_at=now,
        )
        character.content_hash = content_hash_for_character(character)
        db.add(character)

    meld.stage = MeldStage.CAST
    meld.updated_at = now
    await db.flush()
    return len(draft.characters)


def sheet_prompt(character: Character) -> str:
    """The image prompt for one character's reference sheet.

    Built from `appearance` alone, never `description`: the image model has
    not read the story, and feeding it plot would produce an illustration
    of a scene rather than a neutral reference of a person. The framing
    clauses are fixed so that every sheet in a Meld is shot the same way --
    consistency between sheets is what makes them usable as references in
    M4.
    """
    return (
        "Character reference sheet. Full body, front view, neutral pose, "
        "plain light grey background, even studio lighting, photorealistic, "
        "sharp focus on the face. No text, no watermark, no border, no collage.\n\n"
        f"{character.appearance.strip()}"
    )
```

```python
async def _close_hold(db: DbSession, job: Job, *, succeeded: bool) -> None:
    """Every terminal job closes its hold exactly once.

    On success this calls settle with used == held, which writes no row
    today: both M3 actions are a single unit of work, so nothing is ever
    returned. It is still called, rather than skipped, so the invariant is
    one greppable line -- and so the first action with variable units (M4's
    per-shot images) has one place to report what it actually did.

    On failure the whole hold comes back (spec section 4.3), including for
    a provider content refusal, which is terminal rather than retried.
    """
    if not job.credits_held:
        return

    meld = (await db.execute(select(Meld).where(Meld.id == job.meld_id))).scalar_one_or_none()
    if meld is None:
        # Nothing to refund to. A soft-deleted Meld still returns a row, so
        # reaching this means a hard delete raced the worker.
        logger.error("job %s has no meld to settle against", job.id)
        return

    if succeeded:
        await settle(
            db,
            job_id=job.id,
            user_id=meld.user_id,
            held=job.credits_held,
            used=job.credits_held,
            description=job.kind.value,
        )
    else:
        await refund(
            db,
            job_id=job.id,
            user_id=meld.user_id,
            held=job.credits_held,
            description=f"{job.kind.value} failed",
        )
```

```python
async def run_generate_characters(db: DbSession, job_id: uuid.UUID) -> JobOutcome:
    """Extract one Meld's cast from its story.

    Everything the arq task does except talk to arq, so it can be driven by
    an ordinary session with no Redis in the test suite.
    """
    job = await mark_running(db, job_id)
    if job is None:
        existing = (await db.execute(select(Job).where(Job.id == job_id))).scalar_one_or_none()
        state = JobState.CANCELLED if existing is None else existing.state
        return JobOutcome(state, retryable=False)

    meld = (await db.execute(select(Meld).where(Meld.id == job.meld_id))).scalar_one_or_none()
    story = (
        await db.execute(select(Story).where(Story.meld_id == job.meld_id))
    ).scalar_one_or_none()
    if meld is None or story is None:
        await mark_failed(db, job, "This Meld no longer exists.")
        await _close_hold(db, job, succeeded=False)
        return JobOutcome(JobState.FAILED, retryable=False)

    provider = get_llm_provider()
    system, user = build_character_messages(story.text)

    try:
        result = await provider.complete(
            system=system, user=user, json_schema=CHARACTERS_JSON_SCHEMA
        )
        draft = parse_characters(result.text or "")
    except ProviderError as exc:
        logger.warning("generate_characters failed for job %s: %s", job.id, exc)
        if exc.retryable and job.attempts < MAX_ATTEMPTS:
            # No refund: the hold stays until the job is terminal, or a
            # retry would have to take it again and could fail on a balance
            # the user has since spent elsewhere.
            await mark_for_retry(db, job, str(exc))
            return JobOutcome(JobState.QUEUED, retryable=True)
        await mark_failed(db, job, str(exc))
        await _close_hold(db, job, succeeded=False)
        return JobOutcome(JobState.FAILED, retryable=False)
    except Exception:
        logger.exception("generate_characters crashed for job %s", job.id)
        await mark_failed(db, job, "Extracting the cast failed unexpectedly. Try again.")
        await _close_hold(db, job, succeeded=False)
        return JobOutcome(JobState.FAILED, retryable=False)

    await apply_characters(db, meld, draft, job.input_hash)

    # The user may have edited the story while this ran. The rows just
    # written carry the hash of the story this job was queued for, so if
    # that is no longer current they are genuinely out of date and must say
    # so rather than claim fresh.
    await recompute_staleness(db, job.meld_id)

    job.cost_usd = result.cost_usd
    await _close_hold(db, job, succeeded=True)
    await mark_succeeded(db, job)
    return JobOutcome(JobState.SUCCEEDED, retryable=False)


async def generate_characters(ctx: dict[str, Any], job_id: str) -> str:
    """The arq task. Identical in shape to generate_script -- owns the
    session and the redelivery; the work and the retry decision live in
    run_generate_characters."""
    async with SessionLocal() as db:
        outcome = await run_generate_characters(db, uuid.UUID(job_id))
        attempts = (
            await db.execute(select(Job.attempts).where(Job.id == uuid.UUID(job_id)))
        ).scalar_one_or_none()
        await db.commit()

    if outcome.retryable:
        raise Retry(defer=2 ** (attempts or 1))
    return outcome.state.value
```

```python
async def request_sheet(
    db: DbSession, user_id: uuid.UUID, meld_id: uuid.UUID, character_id: uuid.UUID
) -> JobDispatch | None:
    meld = await get_meld(db, user_id, meld_id)
    if meld is None:
        return None
    character = (
        await db.execute(
            select(Character).where(
                Character.id == character_id, Character.meld_id == meld_id
            )
        )
    ).scalar_one_or_none()
    if character is None:
        return None
    if not character.appearance.strip():
        # Refused here rather than in the job, so it costs a 422 instead of
        # a paid image of nothing.
        raise EmptyAppearance

    input_hash = character_image_input_hash(character.content_hash, CharacterImageKind.SHEET)

    # One sheet row per character, rewritten in place on regeneration. The
    # row is created before the job so target_id is stable across retries
    # and the idempotency key means what it says.
    image = (
        await db.execute(
            select(CharacterImage).where(
                CharacterImage.character_id == character.id,
                CharacterImage.kind == CharacterImageKind.SHEET,
            )
        )
    ).scalar_one_or_none()
    if image is None:
        image = CharacterImage(
            character_id=character.id,
            kind=CharacterImageKind.SHEET,
            is_canonical=True,
            input_hash=input_hash,
            state=ArtifactState.GENERATING,
            created_at=datetime.now(UTC),
            updated_at=datetime.now(UTC),
        )
        db.add(image)
        await db.flush()

    dispatch = await ensure_job(
        db,
        meld_id=meld_id,
        kind=JobKind.GENERATE_CHARACTER_IMAGE,
        target_table="character_images",
        target_id=image.id,
        input_hash=input_hash,
    )

    if dispatch.enqueued:
        # Held only when work will actually happen. A cache hit -- these
        # exact inputs were generated before -- is free, per spec 4.1.
        credits = quote_for(JobKind.GENERATE_CHARACTER_IMAGE)
        await hold(
            db,
            user_id=user_id,
            job_id=dispatch.job.id,
            meld_id=meld_id,
            credits=credits,
            description="character sheet",
        )
        dispatch.job.credits_held = credits
        image.state = ArtifactState.GENERATING
        image.updated_at = datetime.now(UTC)
        await db.flush()

    return dispatch
```

The hold is taken **in the same transaction as the job row** — a commit between them would
leave either a job nobody paid for or a charge for a job that does not exist.

```python
    # by id in its own session, so enqueueing first would race it to a row
    # that does not exist yet.
    await db.commit()
    if dispatch.enqueued:
```

```python
import json
import logging
from dataclasses import dataclass
from datetime import UTC, datetime

from sqlalchemy.ext.asyncio import AsyncSession as DbSession

from framemeld.config import settings
from framemeld.models.meld import Meld, ModerationState
from framemeld.providers.base import ProviderError
from framemeld.providers.registry import get_llm_provider
from framemeld.script.hashes import content_hash_for_story

logger = logging.getLogger(__name__)

MODERATION_JSON_SCHEMA = {
    "name": "moderation",
    "strict": True,
    "schema": {
        "type": "object",
        "additionalProperties": False,
        "required": ["allowed", "reason"],
        "properties": {
            "allowed": {"type": "boolean"},
            # Shown to the user verbatim, so the model is told to write it
            # for them rather than for a log.
            "reason": {"type": "string"},
        },
    },
}

_SYSTEM = """\
You decide whether a piece of text may be sent to an image generation \
model for a short film. Refuse only these: sexual content involving \
minors; instructions for real-world violence or weapons; content whose \
purpose is to depict a real, identifiable person in a false or degrading \
way; and content promoting hatred against a protected group.

Fiction is allowed. Dark, violent, frightening and adult themes in a \
story are allowed. You are not a taste filter and not a rating board -- \
refusing ordinary dramatic writing is a worse failure than allowing it.

If you refuse, `reason` is one short sentence addressed to the writer, \
naming what to change. Never quote the text back.
"""


@dataclass(frozen=True)
class Verdict:
    allowed: bool
    reason: str = ""


class Blocked(Exception):
    def __init__(self, reason: str) -> None:
        super().__init__(reason)
        self.reason = reason


async def check(text: str) -> Verdict:
    """Classify one piece of text.

    Fails **open** on a provider error, logging at WARNING. This is the
    same trade D7 made for the rate limiter, for the same reason: the
    provider being down is an availability problem, and converting it into
    "nobody can generate anything" is a bigger outage than the window it
    closes. The gate exists to stop the obvious cases reaching a paid
    provider, not to be a security boundary.
    """
    if not settings.moderation_enabled or not text.strip():
        return Verdict(allowed=True)

    try:
        result = await get_llm_provider().complete(
            system=_SYSTEM, user=text, json_schema=MODERATION_JSON_SCHEMA
        )
        payload = json.loads(result.text or "")
        return Verdict(allowed=bool(payload["allowed"]), reason=str(payload.get("reason", "")))
    except (ProviderError, ValueError, KeyError, TypeError) as exc:
        logger.warning("moderation unavailable (%s); allowing", exc)
        return Verdict(allowed=True)


async def check_and_record(db: DbSession, meld: Meld, text: str) -> Verdict:
    """Classify, and remember the answer against the text it was about.

    Cached on the Meld so pressing Generate twice does not classify twice.
    The cache key is the text's content hash, so a rewrite re-checks -- a
    `passed` verdict must never outlive the words it approved.
    """
    text_hash = content_hash_for_story(text)
    if meld.moderation_hash == text_hash and meld.moderation_state is ModerationState.PASSED:
        return Verdict(allowed=True)

    verdict = await check(text)
    meld.moderation_hash = text_hash
    meld.moderation_state = (
        ModerationState.PASSED if verdict.allowed else ModerationState.FLAGGED
    )
    meld.updated_at = datetime.now(UTC)
    await db.flush()
    return verdict
```

Flagged content is **recorded, not deleted** (spec §4.5), so it can be reviewed.

## What comes after

M4–M6 are deliberately **not** planned in this depth yet. Each one's shape depends on what
M3 actually produces — a plan written now would be a confident guess that rots, and this
project has already paid twice for plans that assumed a provider behaved a particular way.
What follows is the sequencing and the decisions each milestone will have to make, so the
next plan starts from a question list rather than a blank page.

### M4 — Shots (spec §9)

Shot stills conditioned on character sheets, plus speech per shot. The first milestone
where the two-hash rule does the thing it was built for, across two hops.

Decisions it will have to make:

- **`shot_characters` (M3-D2's deferral comes due).** Who populates it? An LLM pass that
  maps the existing cast onto the existing shot list is the obvious answer, and it needs a
  hash and a job of its own, or it is an un-versioned side effect of something else.
- **How a shot image's `input_hash` composes.** Spec §4.1 is explicit that it includes the
  `content_hash` of the shot *and* of every `character_image` referenced. That is the first
  multi-parent hash in this system; `recompute_staleness`'s per-row comparison generalises,
  but the helper that builds the hash does not exist yet.
- **Reference passing at scale.** `ImageProvider.generate(refs=[...])` takes bytes
  (M3-D12). A shot with four characters means four sheets read from storage per call —
  worth a cache, and worth measuring before building one.
- **Speech.** A `SpeechProvider` adapter, `audio_clips`, and the first non-image asset.
  Kokoro is self-hosted and free (spec §6); Gemini TTS is free-tier (spec §6.3). Either way
  `png_dimensions` has an audio-duration sibling to write.
- **Cost.** ~$0.60/Meld (spec §9) — the first milestone where a full generation is a real
  amount of money, and the first where a "generate all shots" button needs a quote for
  *many* units. That is the action M3's `settle` was built for and never exercised.

### M5 — Preview (spec §9)

The scene spec, the Remotion render service, and a free watchable draft. "The first
genuinely impressive demo, and it costs almost nothing to reach."

- **S3/R2 storage becomes non-optional.** The render service is a separate process that
  cannot present a session cookie, so it needs signed URLs — which is the same fix the
  `<img>` same-site trap needs. One piece of work, two problems.
- **The scene spec is a versioned contract** (spec §3.2) between Python and Node. It wants
  a schema test on both sides, not just a dataclass.
- **The render service must stay dumb** (spec §3.1): no database, no auth, no user concept.
  The pressure to let it "just look one thing up" will be constant.

### M6 — Film (spec §9)

Wan 2.2 image-to-video per shot, the final render, download. ~$6/Meld.

- **This is where the credit system stops being a formality.** A single Final render is
  ~2,500 credits against a 500-credit signup grant, so purchasing (spec §10's deferred
  Stripe work) becomes a prerequisite rather than a nicety.
- **Long jobs.** Renders take minutes, not seconds. `useJobPolling`'s 1.5s interval and the
  worker's 300s `job_timeout` were both chosen for a script generation and will both need
  revisiting — the polling hook's own comment says so.
- **Partial failure.** Thirty clip generations where clip 27 fails is the first job that
  should neither refund everything nor charge for nothing. That is a resumable-job design,
  and it is the largest single unknown left in the roadmap.
